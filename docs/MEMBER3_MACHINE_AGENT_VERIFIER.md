# Member 3 guide — Machine Agent + Verifier ↔ blockchain

You need: **Node + `ethers` v6**, these files from Member 1's repo, and three wallets.

| File | Purpose |
|---|---|
| `integration/machinapay.contracts.json` | addresses, ABIs, chainId, RPC, EIP-712 domain (generated by deploy) |
| `integration/signing.ts` | **copy as-is**: id helpers, `hashEvidence`, `signProof`, `signAttestation`, enums |
| `integration/examples/machine-agent.ts` | tested reference for the machine side |
| `integration/examples/verifier.ts` | tested reference for the verifier side |

## Wallets / keys (all throw-away testnet keys, in `.env`, never in git)
| Role | Key | Needs coins for gas? |
|---|---|---|
| Machine M-042 (wallet **and** signer in the demo) | `MACHINE_PRIVATE_KEY` | yes (`seed:mst` sends 0.02) |
| Verifier | `VERIFIER_PRIVATE_KEY` — its **address must equal** `cfg.verifier` (set at deploy) | yes |
| Customer | Member 4's MetaMask | yes + the reward |

If the verifier address is wrong, every attestation reverts with `InvalidVerifierSignature`. The verifier **cannot be changed** without redeploying.

## Provider setup (important)
```ts
import { JsonRpcProvider, Wallet, Contract } from "ethers";
import cfg from "./machinapay.contracts.json";
const provider = new JsonRpcProvider(cfg.rpcUrl, cfg.chainId, { cacheTimeout: -1, staticNetwork: true });
const wallet = new Wallet(process.env.MACHINE_PRIVATE_KEY!, provider);
const escrow = new Contract(cfg.addresses.JobEscrow, cfg.abi.JobEscrow, wallet);
const registry = new Contract(cfg.addresses.MachineRegistry, cfg.abi.MachineRegistry, provider);
```
`cacheTimeout: -1` avoids `nonce has already been used` when you send two transactions back-to-back (e.g. `acceptJob` then `startExecution`). Always `await tx.wait()` before the next step.

## Machine agent flow
1. **Find work:** listen for `JobCreated` (`escrow.on("JobCreated", …)`) or poll `getJobIds`. Only take jobs with `state == 1 (FUNDED)` and `deadline` in the future.
2. **Check yourself:** `await registry.isRegistered(machineId)` and `isActive` (`machineId = encodeBytes32String("M-042")`).
3. `await (await escrow.acceptJob(jobId, machineId)).wait()` → state 2. Caller must be the machine's wallet, signer or owner.
4. `await (await escrow.startExecution(jobId)).wait()` → state 3. Start Member 2's robot now.
5. Robot finishes → build **evidence** (JSON stays off-chain), e.g.
   ```json
   { "jobId":"0x…", "machineId":"M-042", "packageId":"A",
     "target":{"zone":"green","x":9,"y":4}, "finalPosition":{"x":9,"y":4}, "delivered":true }
   ```
   `evidenceHash = hashEvidence(evidence)` (canonical JSON: sorted keys → identical hash on every machine).
6. **Sign the proof** (EIP-712):
   ```ts
   const block = await provider.getBlock("latest");            // use CHAIN time, not Date.now()
   const proof = { jobId, machineId, result: 1, timestamp: block!.timestamp, nonce: randomNonce(), evidenceHash };
   const signature = await signProof(wallet, escrowDomain(cfg.chainId, cfg.addresses.JobEscrow), proof);
   ```
   `result`: `1` = machine reports success, `0` = machine reports failure. **Nonce must never repeat** for the same machine (random 256-bit is fine).
7. `await (await escrow.submitProof(proof, signature)).wait()` → state 4. (Anyone may relay this call; the signature is what authorises it.)
8. **Send `{proof, signature, evidence}` to the verifier** over HTTP (stringify `nonce`/`timestamp` bigints).

Signing key must be the `signer` registered in the registry (demo: same as the wallet). Wrong key → `InvalidMachineSignature`.

## Verifier flow (deterministic, no external AI)
1. Get `{proof, evidence}` from the machine; read authoritative state from chain: `job = await escrow.getJob(jobId)` (must be `state == 4`), `machine = await registry.getMachine(job.machineId)`.
2. Checks (all must hold for PASS):
   - `machine.active`
   - `hashEvidence(evidence) === job.evidenceHash` ← ties off-chain evidence to the on-chain signed proof
   - `evidence.jobId === jobId`, `evidence.machineId === "M-042"`
   - `finalPosition == target` and `delivered === true`
3. Sign the attestation — **`proofHash` must be the on-chain `job.proofHash`**:
   ```ts
   const att = { jobId, machineId: job.machineId, proofHash: job.proofHash, passed, timestamp: block.timestamp };
   const sig = await signAttestation(verifierWallet, domain, att);
   await (await escrow.submitAttestation(att, sig)).wait();
   ```
4. **Settle:** `passed` → `escrow.release(jobId)` (state 5 → 6, pays the machine). Failed → `escrow.refund(jobId)` (customer refunded, state 7). Anyone may call these; the contract fixes the payee, so your service has no power over where money goes.

Contract rules to be aware of: the verifier can't PASS a proof where the machine itself reported `result == 0` (`AttestationContradictsProof`); attestation must arrive within `deadline + 1 h`; signed timestamps must be ≤10 min in the future and ≤1 h old.

## Detect payment / refund
```ts
escrow.on("PaymentReleased", (jobId, machineId, wallet, amount) => …);
escrow.on("JobRefunded", (jobId, customer, amount, reason) => …);   // reason 0 cancelled, 1 expired, 2 verification failed
```
or `await escrow.getJobState(jobId)` → 6 PAID / 7 REFUNDED.

## Suggested HTTP contract between machine agent and verifier
`POST /verify` body `{ jobId, proof:{…,timestamp:"…",nonce:"…"}, signature, evidence }` → `{ passed, checks:{…}, attestationTx, settleTx }`.

## Error decoding
```ts
try { await escrow.submitProof(proof, sig); }
catch (e: any) { const err = escrow.interface.parseError(e.data ?? e.info?.error?.data); console.log(err?.name, err?.args); }
```
Common: `InvalidState` (wrong step/order), `NonceAlreadyUsed`, `ProofExpired`, `JobExpired`, `NotMachineOperator`, `InvalidMachineSignature`.
